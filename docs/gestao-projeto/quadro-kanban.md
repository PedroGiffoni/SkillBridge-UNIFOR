# Quadro Kanban

[Abrir Project nº 2 — SkillBridge — Gestão do Projeto F108](https://github.com/users/PedroGiffoni/projects/2)

| Status | Condição de uso |
| --- | --- |
| Backlog | Trabalho identificado, aguardando seleção e responsável confirmado |
| A fazer | Escopo e dependências compreendidos; selecionado pela equipe |
| Em desenvolvimento | Execução real iniciada; registrar início real e responsável confirmado |
| Em revisão | Entregável disponível, verificação solicitada e evidências vinculadas |
| Concluído | Todos os critérios atendidos e revisão comprovada |

Fluxo: Backlog → A fazer → Em desenvolvimento → Em revisão → Concluído. Falhas de revisão devolvem a atividade para desenvolvimento. Impedimentos devem ser descritos na Issue e no relatório da sprint; não criar conclusão fictícia.

Visualização existente verificada por API: **Kanban Geral**, número 1, layout Board, colunas pelo campo Status, sem filtro que oculte Issues. [Abrir Kanban](https://github.com/users/PedroGiffoni/projects/2/views/1). Filtros por Sprint, Categoria e repositório podem apoiar a revisão. Não foi criado outro Project nem alterada configuração de outros Projects. Limite inicial proposto de trabalho em andamento: uma atividade por integrante ativo, sujeito à confirmação da capacidade. Issues sem responsável confirmado permanecem no Backlog.

Guardar uma captura ou exportação real do quadro durante cada sprint, identificando data real, contexto e autor do registro. Não usar o estado atual como prova de execução futura.
